## 四、典型「启动即崩」模式

状态日志反复出现同一种序列（共约 14 个片段、100+ 次拉起尝试）：

```
✓ 启动成功        ← 进程/端口出现
✗ 服务未运行      ← 30 秒内心跳就丢了（进程退出）
✓ 启动成功
✗ 服务未运行
...
```

**结论性现象**：`启动成功` 说明拉起动作本身成功（进程起来、端口可探活），但**进程在 30 秒内退出**。
即：**harness 启动后立即崩溃/退出**，不是"起不来"，是"起来就死"。

## 六、诊断结论

1. **主要故障形态**：启动后 30 秒内进程退出（启动即崩）。显式 `✗ 启动失败` 共 3 次（L699、L1097、L1103）。
2. **高发场景**：每次重装/升级完成后的一段窗口内；无固定规律——同一安装流程有时能稳定 8 小时以上，有时反复崩溃。
3. **不是配置损坏**：崩溃发生在"装完即跑"阶段，且卸载重装可恢复；`.dsh`（settings/profiles/sessions）在多次卸载中存活（`data` 是软链接，指向 `/vol1/@appshare/DeepSeekHarness`，删软链接不删内容）。
4. **状态日志看不到根因**：`/var/log/apps/deepseek-harness.log` 只有心跳与安装步骤，**没有进程 stderr**，无法直接看出崩溃堆栈。`退出码: 0` 的那次是正常退出（08:33），非崩溃。
5. **当前状态**：08:33:35 重启后运行正常，心跳持续 `✓ 服务运行中`。
