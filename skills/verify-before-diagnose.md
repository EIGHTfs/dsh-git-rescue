# 先实测，再诊断（verify-before-diagnose）

> 来源：2026-08-19 事故——救援实例 AI 凭原机（10.10.10.121）"只读卷/无限重启"旧事故脑补本机（10.10.10.4）故障，声称 /vol1 只读、主实例未运行、需 remount；实测全部相反（/vol1 rw、主实例 200、无需 remount）。**教训：诊断不实测 = 编故事。**

## 一、诊断前必须先实测（一条都不能少）

| 断言 | 必跑实测 |
|---|---|
| "卷只读/写不进" | `mount | grep /vol1` + `touch` 写测试 |
| "服务没起来" | `curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:<端口>/` |
| "进程在/不在" | `ps -ef | grep <进程>` 或 `ss -tlnp | grep :<端口>` |
| "磁盘满/坏" | `df -h`、`zpool status`（ZFS）、`dmesg | tail` |
| "配置/文件状态" | 直接 `cat`/`ls` 目标文件 |
| "哪个实例/路径" | `pwd`、`echo $DSH_HOME`、核对实际 home 路径 |

**禁止**：凭历史经验、凭记忆中的旧事故、凭"看起来合理"脑补结论。

## 二、地址规则

- 给访问地址前 `hostname -I` 确认本机真实 IP；禁止沿用旧文档/旧机器（如 10.10.10.121）里的地址
- 详见 host-address-convention

## 三、插件 GitHub 仓库地址

- 查任何插件/项目的 GitHub 地址 → 加载 `dsh-repo-index`（唯一权威索引），不要凭记忆或复制别处地址

## 四、诊断流程模板

```
1. 实测：<列出跑过的命令 + 输出关键行>
2. 结论：<基于实测的结论>
3. 方案：<下一步>
（没有实测输出 = 结论不可信）
```
